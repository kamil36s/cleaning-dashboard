# Data semantics and limits

All snapshot files are generated by deterministic rules. The exporter does not call an AI model and does not write interpretations.

## Reliability

- Treat explicit counts, dates, sums, averages, and supplied trend labels as calculated facts.
- Compare periods only when both sides contain usable observations. `null` means the comparison is unavailable.
- Available-observation averages do not imply that missing days had a value of zero.
- A source may be stale. Inspect the observation dates and `source_freshness` before interpreting it.
- Opaque IDs are only for relating records within the same dataset. Do not infer identity or location from them.

## Privacy reductions

Task titles, event titles, cleaning task text, addresses, free-text notes, device identifiers, raw packets, prompts, authentication data, and external-account caches are deliberately absent. Habit names and book titles/authors remain because their meaning is necessary for analysis.

## Metric conventions

- `*_change_pct = (current - previous) / previous * 100`.
- A trend is `unknown` when comparison data is unavailable. Dataset-specific tolerances avoid labeling tiny changes as directional.
- Cleaning due dates are calculated from the last completion date plus the configured recurrence interval.
- Habit `positive_days` indicates recorded positive behavior, not necessarily target attainment.
- The deterministic summary contains candidates worth inspecting; it does not assert causes.
